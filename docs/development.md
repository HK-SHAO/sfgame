## 实现要点

美术：极简矢量风格（做好兼容性、可迁移性，目标是未来可以随时把素材替换掉），物体用纯色几何图形，善用粒子系统（小点）表示和可视化风。

引擎：利用好Web、浏览器特性，能够很好的兼容Chrome、IOS Safari，物理用简单的2D刚体+预设力场），善用流体模拟（基础力学、拉格朗日视角、欧拉视角之间要耦合好，善用先进且成熟的算法）。

为什么要做好拉格朗日视角、欧拉视角之间要耦合好：这个拉格朗日视角，相当于模拟很多小球在碰撞，所以呢，会把那个流体说把什么空气呀水呀，把它想象成有一堆小小的小球很纯粹的小球，他们在疯狂的互相碰撞。欧拉是欧拉视角就是不关注这些玩意儿，原来是由什么分子原子这些小球组成，而是有一个很神奇的一块一块的空间组成的，这些空间有很多概念，比如说它有温度的概念，它有压强的概念，然后还有整体的那种力的概念等等。拉格朗日视角模拟这些小球之间的运动，其实呢，它运用在钢铁模拟上就很方便，比如说你可以把手机看作一个盒子，然后它可以跟桌子啊什么的地板碰撞，然后纸飞机也是也可以几乎看作一个钢体，很多时候这些简单的一些模型，一些物体，它可以看作是拉格朗日视角上的些运动的模拟而欧拉视角就很擅长去看待流体，比如说空气的运动，比如说这个液体水的运动。

## 开发守则

- 对于不确定的、疑似陈旧的、遇到困难的要及时联网搜索最新的、可靠的资料作为参考
- 有疑惑、不懂或缺少信息时，优先通过网络（如搜索引擎、Github、官方 docs 等）结合可靠性、时效性获取文档
- 做好平台兼容性
- 优先采用 bun 作为包管理器和运行时，而非 npm/node。优先采用 TS/JS
- 优先采用 vite + lit 作为 web 开发的基础。常用功能可以自己做成模块或库（可以放到 los-app/src/libs）
- 优先采用 web 自带的能力和规范，减少引入依赖项。可以联网参考某些轮子的实现，但对于小型功能避免直接用包管理器引入更多依赖。（大型库可以采取成熟的依赖项，比如 PixiJS、Matter.js、three.js）
- 做好取舍，经常考虑鲁棒性、一致性、全局观。少即是多，简单易懂大于复杂大于杂乱无章
- 做好对生命周期、内存、事件、流等状态的管理。可能耗时的任务做好异步、进度反馈，避免阻塞或卡顿
- 优先遵循最佳规范，优先级最大是 apple 规范，其次是 google 规范、meta 规范。应用在无论是 UI/UX 还是架构、工程还是小到每一行代码
- 优先考虑移动端 UI/UX 设计（当然也能适应桌面端更好），不为不同屏幕尺寸做太多冗余逻辑
- 优先为汉语母语者设计 UI/UX、文案，简约自然，可以参考 Apple 的习惯
- 项目主体是一个单页面应用程序 SPA，减少对服务器的依赖
- 可以利用好 ./skills 中的技能


## 重要提醒

- 优先考虑游戏交互和设计、而非通常的 app 页面布局UI/UX
- 操作、交互设计要简洁，避免复杂的按钮、按键或触控等操作，适配好手机、平板等屏幕尺寸的触摸操作
- 本着第一性原理，简化项目复杂度，少即是多
- 非必要不注释，让代码就如注释一般清晰、好懂、可维护。实在需要补充高信息量的上下文时，可以注释
- 对待项目、代码，始终要克制化
