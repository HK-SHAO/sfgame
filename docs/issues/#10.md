# #10 关卡系统化：可序列化协议、原子能力、三个新教学关、搭建 skill

- **状态**：已实现 + 按「#10 的验收」完成深度 CR 与研发（2026-08-05：`bun run check` 全绿 111 项 + 浏览器一致性逐关通过）；待老大实玩验收
- **日期**：2026-08-04（实现）/ 2026-08-05（验收研发）

## 需求拆解（老大原话要点）

1. 已有 2 关视为教学热身，再设计 **3 个教学关**（完成度要高、充分验证）
2. 设计**基本元素/原子能力**，可像积木一样组合出新关卡；**每个关卡完美可序列化**，方便玩家 DIY 传播
3. 要有**乘法式/涌现式**的原子能力；**不堆砌**，只精选少量原子
4. 关卡与状态可在**无头引擎**内运行模拟（调试/算法/AI 接入）
5. 设计要义与行业经验**搜索高质量资料**学习
6. 浪漫感：信息论、熵、庞加莱回归、宇宙演化
7. **不设限但克制**：不膨胀、做好取舍
8. 补充指示：曲线用**表达式/path**而非采样；序列化考虑 **YAML**；控制通关时长；参考答案须实际可行且耗时优秀；无头与浏览器一致；搜索算法先估复杂度、超时/分段、及时输出

## 协议 v1（levels/*.yaml）

**六个原子字段**：`world`（世界/网格）、`ground.expr`（地形表达式）、`budget`（热/冷源预算）、`spawn`（起点与初速）、`goals[]`（站点序列）、`ambient`（常风 + 可选潮汐）。`solutions[]` 内嵌参考解（含实测 winTime），随关卡一起传播。

- **序列化 = YAML**：可读、可注释、锚点复用；`yaml` 依赖（2.9.0）。运行时经 `parseLevelText` → 校验 → `LevelDef`。
- **地形 = 表达式字符串**：`y = f(x)`，自研迷你求值器（`src/game/expr.ts`，零依赖，~140 行），函数表 `abs min max clamp step smoothstep sin cos exp sqrt pow`。**不用采样折线**（不精准、密度低），**不引 path**（与表达式重叠、求值复杂）——按老大指示做好取舍，不堆积。
- **不引 mathjs**：关卡曲线只需少量初等函数，自研求值器体积为零头；mathjs 会使包体膨胀，与"克制"冲突。
- **新原子（仅两个，均通过第二关测试）**：
  - **站点序列**：`goals[]` 按顺序飞行抵达（每个站点仍须"飞行"而非贴地滑入）。乘法式：1 架飞机 × N 站点 = 接力/旅程谜题。
  - **潮汐风**：`ambient.tide {period, ampX, ampY, phase}`，常风上叠加确定性正弦分量。乘法式：时间成为资源。

## 关键取舍记录（克制化）

- **放弃"对流传动"作为独立教学关**：热+冷并排的水平风在强热柱中轨迹混沌、摆放 ±1 结果剧变（与 #8 翻山关同因），多次数值实验不鲁棒——用「站点序列 + 潮汐」两个更稳的原子替代，热+冷组合留给玩家在 L1/L2 习得的技能自由发挥
- **砍 points/path 地形**：只留表达式（精准、高密度、可移植），三种表达是堆功能
- **不引 mathjs**：迷你求值器零依赖
- **YAML 而非 JSON**：可读、可注释、锚点复用；运行时解析为同一协议对象
- **潮汐保留**：L4 实测对周期/幅值不敏感（14-22s/2.2-3.4 均通关）、无操作稳定失败，配得上一个原子
- **搜索方法论**（按老大指示）：两段式粗筛/精验、组合复杂度预估、墙上时间预算、每 N 配置打印进度——已沉淀进 pitfalls G6 与 skill

## 验收研发报告（2026-08-05）

对上一 commit 做了全量 CR（代码/测试/脚本/skill/文档），按「#10 的验收」六条逐项研发。全部改动经 `bun run check`（typecheck + 111 测试 + build）与 headless Chrome 一致性验证（每关参考解差 ≤0.05s、挂机 15s 不通关）。

### 1. 参考答案搜索：稳定高性能算法 + skill 沉淀

把 `run-level.ts --solve` 从"随机重启爬山"升级为**多目标遗传算法 + 多 worker 并行评估**（`--workers`，默认核数−1）：

- 种群 32、精英保留、锦标赛选择、均匀交叉、邻域变异、停滞自动重启；
- **种子注入**：种群首代包含 YAML 已登记的参考解，搜索至少保住现状；
- 产出**候选榜**（前 5 个互不相同的通关解），逐一 `--verify --robust` 复核后选入 YAML；
- 算法、参数、反模式全部沉淀进 `skills/level-design/SKILL.md` §6。

实测踩到并修复的三个搜索坑（也回写了 pitfalls）：

- **粗筛假阴性**：`dt=1/30` 是"另一套物理"——连已知参考解在粗筛下都可能不通关（L1 参考解粗筛 60s 挂、精筛 22.2s 通）。搜索改为**直接精筛 `dt=1/60`**（cap 35s + 贴地早退），彻底消除 dt 假象（G6 更新）。
- **刀刃解**：GA 曾找到 y=26.832 的解，URL 只保留 1 位小数（26.8）后不通关——玩家无法复现。评估器对**所有候选坐标做 1 位小数舍入**后再模拟，"URL 可放置"成为硬约束。
- **字面"路程优先"的病理解**（见下条）。

### 2. 参考解优先级：路程 → 少贴地 → 少耗时（含关键取舍）

纯字面"路程优先"经实测会选出病理解：L1 出现贴地爬行 14s 的"短路程"解（118.9 vs 125.2）；L2 出现路程短 9% 但耗时多 95% 的解（27.5s vs 14.1s）。两者都违背"更平稳、更舒服"的初衷，故最终准则为：

1. 必须通关；
2. **基本全程飞行**（贴地 ≤1.5s 硬性底线）；
3. 组合质量 `路程 + 0.8×耗时`（路程为主、耗时次之，1s 耗时 ≈ 0.8 单位路程，杜绝"短 1 单位路程换慢 10 秒"）。

参考解重搜/重验结果（路程/贴地/耗时均实测）：

| 关 | 解 | 通关 | 路程 | 贴地 | 扰动鲁棒 |
| --- | --- | --- | --- | --- | --- |
| 1 | 冷压热托：(38,45.4)热+(50,21.3)冷 | **16.9s**（旧 22.2s） | **79.5**（旧 125.2） | 0.8s | 63%（旧 44%） |
| 2 | 冷源双降：(36,24)+(45,30) 冷 | 14.1s | 79.4 | 0s | 81% |
| 3 | 单热源翻山脊：(26,28) 热 | 8.8s | 39.5 | 0s | 100% |
| 4 | 孤山热源：(32,44) 热 | 11.5s | 57.5 | 0.1s | —（重验通过） |
| 5 | 双热源接力：(16,29.3)+(60,17.3) 热 | **18.1s**（旧 23.6s） | 71.9 | **0s**（旧 12.4s） | 75%（旧 94%） |

- **L1 采纳混合源新解**：路程 −36%、耗时 −24%，比纯热源候选中最好的（22.2s/44%）全面更优；它本身就是"热+冷组合原子"的涌现用法（skill 的组合语法早已预言）。L1 的提示文案仍以"热源托升"为核心教学，参考解展示进阶组合。
- **L5 采纳全程飞行新解**：旧解贴地滑行 12.4s（正是验收第 2 条反对的"接触地面"），新解全程飞行且快 5.5s，鲁棒 75% 达教学关门槛。
- **L2/L3/L4 保留原解**：重搜后原解仍是最优或近优（L3 的 8.2s 替代解鲁棒掉到 75%，不值得；L2 的 20.4s 替代解只省 7 单位路程却慢 6.3s，且第一枚源压在出生点旁不直观）。
- 诚实披露：L1 因崖壁地形本身刀刃（源位置 ±1 敏感），最佳已知解鲁棒 63%，未达 75% 教学门槛但显著优于旧解（44%）；不改变关卡几何以免破坏已验收的教学结构。

### 3. 暂停物理时间

- **过关即冻结**：`LevelSimulation` 在 `phase==='won'` 的同一时刻停止步进——时间、流体、纸飞机全部冻结（结算弹窗弹出后背景不再运行，飞机不会被吹走）；计时冻结在通关时刻。无头测试守护（`sim-pause.test.ts`）。
- **dev 模式空格暂停**：`?dev=1` 下空格随时暂停/恢复整个物理时间（忽略按键重复、阻止页面滚动）；暂停时风声淡出、粒子/拖尾/风声音效同步停摆；暂停状态显示在 perf 叠加层行尾。过关冻结为绝对行为，dev 空格不能解除（防止飞机被吹走）。

### 4. 过关逻辑与旗子视觉/音效

- **过关 = 全部站点"抵达过"**（顺序无关，每站仍须飞行抵达）：简化判定、不强迫先后关系；渲染/提示/测试/协议注释全部同步（L3/L5 的顺序强制测试改为集合语义测试）。
- **经过旗子的"奖励"音效**：`sfx.reward()` 双音上行，与过关四音琶音明显区分；每抵达一站响一次（最后一站由过关音收束）。
- **旗子视觉统一（按建议从简）**：所有未抵达旗 = 虚线圆（抵达范围）+ 旗帜；**已抵达只留旗杆**，虚线圆等提醒效果消失；删除了底部运动的圆环与旗杆后的半透明绿色矩形光柱——第一旗与后续旗完全同构。虚线圆从背景烘焙移到动态层，才能随抵达即时消失。

### 5. L4 风速归零瞬间气流消失

根因：`drawTracers` 在风速平方 < 0.16 时**硬截断**整片线条/粒子，潮汐风过零的瞬间全部骤隐。修复：去掉硬截断，线条透明度随风速连续变化（gust 0.7→1.3），归零瞬间气流以弱残影可见；粒子在静止时本就按路程存留（#4 的设计），不再出现"消失→出现"的闪烁。
