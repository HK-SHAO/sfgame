# #10 关卡系统化：可序列化协议、原子能力、三个新教学关、搭建 skill

- **状态**：已实现、自测通过（`bun run check` 全绿 + 浏览器一致性验证逐关通过）；待老大实玩验收
- **日期**：2026-08-04

## 需求拆解（老大原话要点）

1. 已有 2 关视为教学热身，再设计 **3 个教学关**（完成度要高、充分验证）
2. 设计**基本元素/原子能力**，可像积木一样组合出新关卡；**每个关卡完美可序列化**，方便玩家 DIY 传播
3. 要有**乘法式/涌现式**的原子能力；**不堆砌**，只精选少量原子
4. 关卡与状态可在**无头引擎**内运行模拟（调试/算法/AI 接入）
5. 设计要义与行业经验**搜索高质量资料**学习
6. 浪漫感：信息论、熵、庞加莱回归、宇宙演化
7. **不设限但克制**：不膨胀、做好取舍
8. 补充指示：曲线用**表达式/path**而非采样；序列化考虑 **YAML**；控制通关时长；参考答案须实际可行且耗时优秀；无头与浏览器一致；搜索算法先估复杂度、超时/分段、及时输出

## 协议 v1（levels/*.yaml）

**六个原子字段**：`world`（世界/网格）、`ground.expr`（地形表达式）、`budget`（热/冷源预算）、`spawn`（起点与初速）、`goals[]`（站点序列）、`ambient`（常风 + 可选潮汐）。`solutions[]` 内嵌参考解（含实测 winTime），随关卡一起传播。

- **序列化 = YAML**：可读、可注释、锚点复用；`yaml` 依赖（2.9.0）。运行时经 `parseLevelText` → 校验 → `LevelDef`。
- **地形 = 表达式字符串**：`y = f(x)`，自研迷你求值器（`src/game/expr.ts`，零依赖，~140 行），函数表 `abs min max clamp step smoothstep sin cos exp sqrt pow`。**不用采样折线**（不精准、密度低），**不引 path**（与表达式重叠、求值复杂）——按老大指示做好取舍，不堆积。
- **不引 mathjs**：关卡曲线只需少量初等函数，自研求值器体积为零头；mathjs 会使包体膨胀，与"克制"冲突。
- **新原子（仅两个，均通过第二关测试）**：
  - **站点序列**：`goals[]` 按顺序飞行抵达（每个站点仍须"飞行"而非贴地滑入）。乘法式：1 架飞机 × N 站点 = 接力/旅程谜题。
  - **潮汐风**：`ambient.tide {period, ampX, ampY, phase}`，常风上叠加确定性正弦分量。乘法式：时间成为资源。

## 关键取舍记录（克制化）

- **放弃"对流传动"作为独立教学关**：热+冷并排的水平风在强热柱中轨迹混沌、摆放 ±1 结果剧变（与 #8 翻山关同因），多次数值实验不鲁棒——用「站点序列 + 潮汐」两个更稳的原子替代，热+冷组合留给玩家在 L1/L2 习得的技能自由发挥
- **砍 points/path 地形**：只留表达式（精准、高密度、可移植），三种表达是堆功能
- **不引 mathjs**：迷你求值器零依赖
- **YAML 而非 JSON**：可读、可注释、锚点复用；运行时解析为同一协议对象
- **潮汐保留**：L4 实测对周期/幅值不敏感（14-22s/2.2-3.4 均通关）、无操作稳定失败，配得上一个原子
- **搜索方法论**（按老大指示）：两段式粗筛/精验、组合复杂度预估、墙上时间预算、每 N 配置打印进度——已沉淀进 pitfalls G6 与 skill
