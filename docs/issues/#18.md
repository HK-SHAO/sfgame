# #18 bun check 测试提速：删高耗时与冗余测试

- **状态**：已完成，`bun run check` 全绿
- **日期**：2026-08-06

## 基线

`bun run test` 墙钟 **44.2s**（测试 CPU 时间 83s，19 文件 139 项）。大头：

| 测试 | 耗时 |
| --- | --- |
| solutions「零操作挂机不能通关」（150s×5 关模拟） | 36.3s |
| 各关「无操作…」用例（level1~5） | ≈15s |
| solutions「每个解一次放置通关」 | 7.3s |
| level4 潮汐/无操作、level2 计时/基准策略 | ≈7s |
| fluid 两条物理确定性 | 2.1s |

## 删除/降级（按工单"大胆删除"）

- **零操作挂机回归：整条删除**（工单点名）。降级为设计红线：新关卡验收用 `run-level.ts --sim` 跑 150s 挂机自查（level-design skill 已同步）
- 各关全部「无操作」用例（与上同族，重复覆盖同一不变量）
- 各关「参考答案通关」用例——与 solutions「每个解通关」完全重复（同一坐标表）
- 跨关重复的放置规则（只留 L2 最全一份）、抵达语义（只留 L2 贴地+飞入合并一条）、初始状态（只留 L2）
- fluid「物理确定性」×2（单线程无 RNG，确定性不言自明）
- **clouds.test.ts 整体删除**（纯视觉 13ms；行为由玩家反馈验收）
- **level1/level3/level-helper 文件整体删除**（上列删完后无剩余内容）
- 过细项：batch 的 dashRing/arc/discGrad 顶点计数、loop 的 4×/120Hz/运行时切速、url-state 的 dispose 等

## 结果

19 文件 139 项 → **16 文件 36 项**；墙钟 **44.2s → 5.9s**（测试 CPU 83s → 9.8s，约 7 倍）。保留项均为无替代的核心白盒：注册解通关、流体升降风、贴地边界层、定步长循环、URL 状态协议、关卡 YAML 校验/序列化、进度容错、暂停/过关冻结。
