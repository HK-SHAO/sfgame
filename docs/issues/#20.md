## 交付内容

流体内核（唯一 CPU 热点，~99% 每帧数值成本）整体迁移到 AssemblyScript → WASM·SIMD：

- `assembly/core.ts`（状态/标量通路：采样、addHeat、半拉格朗日平流、涡度、边界）+ `assembly/main.ts`（SIMD 入口）
- 单一产物 `src/sim/wasm/sfsim.wasm`（**仅 SIMD 变体**，按指示移除标量变体；不支持 SIMD 的环境自动落回 JS 后端）
- 后端抽象：`FluidLike` 接口 + `createFluid()` 工厂（`wasm-fluid.ts`），`LevelSimulation` 与刚体/粒子/云/渲染全部按接口消费；JS `fluid.ts` 保留不动
- 切换：URL `?be=js|wasm`（state.ts）、dev 页面「物理后端」按钮（重载生效）、无头 `--backend js|wasm|auto`
- 无头加速：`run-level.ts --verify/--solve/--sim` 与 solve-worker 子进程均走 wasm
- 对照工具：`scripts/bench-backend.ts`（js vs wasm 的 ms/step + 通关时间/路程一致性）
- 引导：`main.ts` 异步预载（`?url` 资源，失败静默落回 JS 绝不阻塞）；`wasm-boot.ts` 平台无关（浏览器 fetch / bun 读文件由调用方注入，保持 src/ 无 DOM）

## 精度决策（重要）

初版按「游戏级精度」用 f32x4 车道（压强 GS/散度/梯度/浮力），实测**逐位不可行**：

- 混沌流场（李雅普诺夫指数 ~2.2/步）会把任何 f32 舍入指数放大：f32 GS 下 60 步后场差异即饱和到 O(100)，5 个注册解 3 个失效（含第一关教程），f32 平流补偿曾让第 5 关解从 18.1s 恶化到 55s
- 「玩法不变」是不变量（老大授权改测试的前提），故流体全链路保持 f64 语义——**f64x2 车道运算与 JS 的 f64 中间量逐位一致**，最终交付反而达成比"允许不一致"更强的结果：**两后端逐位相同**，5 关全部注册解在 wasm 通关时间与记录精确一致（14.1/16.9/16.8/11.5/18.1s）

SIMD 覆盖面：浮力、平流误差补偿、散度、压强 GS（8 格组红黑双趟）、梯度回减（f64x2 车道，f32 存储侧 promote/demote）；半拉格朗日回溯（gather）与涡度保持标量。GS 组车道按行奇偶分发（组首格 ≡1 mod 8，车道奇偶随行翻转）。

## Worker/共享内存（评估后不采用）

SharedArrayBuffer 需 COOP/COEP 响应头，破坏本 SPA 零配置静态部署（任意静态托管/iOS WebView）；无头并行已由 solve-worker 子进程承担（每进程内再获 wasm 加速）。主线程同步 WASM 是固定步长 60Hz 模拟的最稳形态。
