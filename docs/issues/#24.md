## 二、no-js 化（HTML/CSS 原生替代）

- **storage-view 展开/收起**：`expanded` state + 按钮 → 原生 `<details>/<summary>`，open 状态由浏览器维护，零 JS。删除 `@state expanded`、`toggleExpand`、条件渲染。收起/展开文字用双 span + `details[open]` 选择器切换显示。删除按钮在 summary 内，`preventDefault+stopPropagation` 防止误触开合（已实测验证）。
- **dev-menu 开发者模式开关**：button + `.on` class → 原生 `<input type="checkbox">`，`input:checked + .switch` 驱动滑块/变色（纯 CSS），键盘可聚焦，补了 `:focus-visible` 轮廓。可访问性比原实现更好。
- **level-editor 折叠**：曾改用 `<details>/<summary>`；按老大反馈已改回 JS 方案（expanded state + caret 旋转动画，见「〇」）。
- win-overlay 等其余交互均有瞬态/事件需求，强行原生化只会绕弯，未动。

## 四、内存泄漏审计

静态审计 + headless Chrome 实测（无头循环进入/退出游戏关，UI 范畴，非玩法验证）：

- **静态**：controller.destroy 完整（loop rAF 取消 + setTimeout 入口守卫、input 监听、ResizeObserver、window resize、status bar DOM）；dev-panel disconnect 移除 resize 监听、自身上监听随元素 GC；storage 的 disarmTimer 断开时清理；sfx 手势监听 `{once:true}`、音频节点 ended 后 disconnect；trail/tracers/clouds 全部固定容量 typed array；渲染零每帧分配。
- **实测**：SPA 导航循环 24 次进/出游戏（每轮新建 wasm 实例 + 渲染器 + 400 粒子）：DOM 零残留（sf-game/sf-status/sf-dev-panel 均为 0），JS heap 8.7MB → 稳定回落无线性增长——每关新建的 wasm 实例可被 GC 回收，无泄漏。
- 结论：无需要修复的泄漏。唯一"永久监听"是 sfx 单例的 visibilitychange（页面生命周期，无累积）。
