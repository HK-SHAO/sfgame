# #24 AssemblyScript 全量迁移 C/emcc（含渲染批内核）

- **状态**：已完成，`bun run check` 全绿；解法 ±2s / batch 位断言 / bilinearSample parity 全部无漂移
- **日期**：2026-08-06

## 背景与决策

#20/#23 的 WASM·SIMD 内核基于 AssemblyScript（asc）。经基准验证 emcc（C/emcc，`-O3 -msimd128` 自动向量化）三引擎全面更快（bun +23%、Chrome +20%、Safari +18% 平均吞吐），且数值确定性可保持（解法时间、batch 顶点、采样 parity 均无漂移）。据此大胆全量迁移并清理 asc 残留。

## 迁移内容

- **`native/`**（新）：`engine.c` 流体内核（原 assembly/core.ts + main.ts，标量 + LLVM 自动向量化）、`batch.c` 渲染顶点批内核（原 assembly/batch.ts 全量移植，musl 三角函数与旧版同源故位一致）、`build.sh`（emcc 双文件一次链接 → `src/wasm/sfengine.wasm`，`-ffp-contract=off` 保 IEEE 语义，产物路径不变故 JS 引导零改动）
- **删除**：`assembly/` 全部 5 文件、package.json 的 assemblyscript 依赖、dev.ts 的 asc 编译与监视（改监视 `native/*.c`）
- **bench 收敛**：`bench/c/` 移除（fluid.c 已提升为正式内核）；bench-server/bench.ts/bench-page 去掉 asc 对比维度，回到单内核多浏览器
- 注释/AGENTS.md/README 全部引用更新

## 验证

- 53 项测试全绿：**解法 ±2s 无漂移**（emcc 数值与 asc 逐位不同，但混沌漂移落在容差内，无需重录解法）、batch 顶点位断言通过、bilinearSample parity 通过、容量边界 161×121 拒绝 ✓
- 基准（迁移后内核）：101×75 现状关卡 bun 0.75/Chrome 0.88/Safari 0.85-0.92ms；平均吞吐 9.0-10.3k 格/ms（迁移前 asc 8.3-9.6k）
- 产物 21.4KB（asc 16.9KB），零导入，SIMD 依赖与旧版一致
