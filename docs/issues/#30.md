# #30 反馈音效、震动与程序化背景音乐

状态：v3 已执行完毕（2026-08-08），待老大试听验收。试听文件 `sfgame-web/.local/bgm-v3.wav`（48s，bpm=80，seed=1）。

## 演进脉络

- **v1**：纯 sine 环境音乐 + lookahead 调度（Eno 式），音效沿用 sfxr 参数体系。老大反馈：音色旋律单薄。
- **v2**：参考 AlphaChord 编曲思想重写乐谱——人工作曲 THEME 根本旋律（动机重复=记忆点）、1645/1625/6451 走向、节奏型库、FM 音色、setFlow 实时变奏；音效加 fmTone/noiseBurst 个性音色（热源下滑音+噪声爆点、冷源 FM 冰晶双音、过关 FM 电钢终止式）。老大反馈：音色仍不够好，尤其 BGM。
- **v3（当前）**：音色跨越——移植 Shadertoy 物理建模钢琴进 WASM，离线烘焙 stem loop。

## 资料学习摘要

- **`.local/sound1.glsl` / `sound2.glsl`**（Shadertoy iq/penguinPiano 物理建模钢琴）：真实钢琴音色 = 十余个**非谐波拉伸分音** `fn = n·f·√(1+B·n²)`（钟感根源）× **失谐多弦**（±0.00025 出丰盈合唱感）× **分音独立衰减** `exp(-t(0.4+0.12n))` × **力度控亮度** `pow(n,-(1-v)·0.8)` × 15ms 余弦起音窗 × 琴体共鸣瞬态 × tanh 软饱和。bass 用 tanh 出幻影分音。
- **`.local/AlphaChord-master`**：1645 万能走向、种子驱动旋律限定音阶、动机重复、奇偶小节疏密、伴奏音量压于主旋律。
- **jsfxr/WebAudio 调度**（v1 沿用）：一次性音效 = 波形 + 包络 + 频率 ramp；音符靠 `ctx.currentTime` 时间轴不靠 setTimeout。

## 性能架构决策

BGM 是 ~24s 确定性循环，无需实时合成。三案比较：

| 方案 | 结论 |
|---|---|
| **WASM 离线烘焙 stem loop**（选） | 烘焙一次 ~2.2s → AudioBuffer + AudioBufferSourceNode loop，播放零合成成本 |
| WebGL 渲音频（弃） | readPixels 回读同步阻塞；音频非 GPU 负载，占着渲染管线反而拖累 |
| 实时逐音符合成（弃） | OscillatorNode 做不了物理建模（分音/失谐/独立衰减需逐采样控制） |

- **合成器优化**：第一版直接移植 12.6s → 重写为 2048 点正弦查表（线性插值）+ 增量包络（exp 转逐采样乘子），每采样零超越函数（除一次 tanh）→ 2.5s，5× 提速。
- **分片烘焙**：每片 8 音符 + `setTimeout(0)` 让出主线程，总耗不变但解锁后不卡帧；start/stop 代际竞态护栏。
- **循环无缝**：尾音折回头部叠加（`pcm[s % pcmLen] +=`），不加尾余量（会破坏循环周期）。

## v3 架构（音乐部分）

- **`assembly/music.ts`（新）**：钢琴物理建模内核（bass/arp/theme 三轨同引擎，力度分层），导出 `mClear/mRender` + pcm/score 零拷贝指针；模块级 StaticArray 复用，stub runtime 零分配。编译进既有 sfengine.wasm 单模块（gzip 后 17.66 kB）。
- **`app/core/music.ts`**：`bakeScore(seed)` 不变（THEME 36 音符人工作曲 + 1645 走向 + 奇偶节奏型）；`MusicPlayer` 改为 stem 播放器——两 stem（伴奏/根本旋律）分别烘焙为 AudioBuffer 循环源；旋律层经 melLp 低通 + 共享反馈延迟（0.26s）出空间感；总线 0.24，过关 duck 至 0.11。
- **实时变奏（v2 延续）**：`setFlow(x)`——飞机相对风速驱动旋律层增益（0.25+0.75v）与低通截止（900+2400v），controller 每 tick 变化超 0.04 才推送；暂停时压至 0.15。
- **降级保护**：合成内核（createEngine）不可用时静默降级为无音乐，物理内核不受牵连。
- **启动预烘焙（2026-08-08 补，根除进关前几秒掉帧）**：掉帧根因是 stem 烘焙在关内主线程执行（分片 ~150ms/片仍吃帧）+ 每关 WASM 实例化 + 首帧着色器编译。解法：①烘焙移 Worker（`music-bakery.ts` + `music-worker.ts`，主线程零开销，产物 transfer 回传、单槽缓存、12s 预算护栏）；②音乐启动三级路径：预烘缓存即起 → Worker 后台烘 → 失败回退主线程分片烘；③`takeEngine` WASM 实例池（预烘期备好、取后后台补）；④`GlRenderer.warmup` 抛弃式画布热身着色器/背景纹理；⑤启动预热与运行时校验全收进自治模块 `app/ui/prewarm.ts`（流水线+校验+状态 UI 高内聚，app 只挂载 `<sf-prewarm>` 与查 `prewarmPassed()` 门禁）；关内闲时预烘下一关。
- **预热模块重构与烘焙提速（2026-08-08 二补）**：①预热带弹窗解耦为 `prewarm.ts` 单模块，app.ts 删掉全部编排逻辑；运行中不再遮挡首页，改底部小字（不拦输入），完成后自动消失。②预热兼作运行时校验：引擎（WASM 实例化）+ 渲染（WebGL 全链路热身）为关键项，不过则弹可关警告并阻断进关（`prewarmPassed()` 门禁，startGame/openSolution）；音乐烘焙仅增强项不计入（有回退）。③烘焙产物持久化 IndexedDB（每关 ~8MB 超 localStorage 配额）：二级加载起零烘焙；版本戳 `STEM_CACHE_V` 随合成内核变更 bump，封顶 24 条逐最旧；缓存纳入存储管理页（`listStemCache`/`deleteStemCache`，逐条/全清两步确认，全清同时覆盖 localStorage）。④合成内核提速 ~45%（2.6s→1.4s）：释音后能量低于 -54dB 提前截断（短音符省掉固定 2.2s 尾）+ 高分音衰减收缩 active（已静音尾部音不再查表）。
