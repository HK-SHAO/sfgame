# #7 性能与流畅度大幅提升（渲染 GPU 化 + wasm 物理加速）

- **状态**：两轮均实现、自测通过（`bun run check` 84 项全绿）；iOS 实机体验待老大验收
- **日期**：2026-08-04（第一轮渲染 GPU 化；第二轮 wasm 求解器；补充：倍速卡顿诊断与修复）

## 第一轮诊断：瓶颈在渲染栅格化，不在物理

- iOS Safari 的 Canvas 2D 为 **CPU 栅格化**（WebKit）。旧渲染每帧 ~400 粒子 × 24 轨迹点 ≈ **9600 段描边**，即使分桶也要 20+ 次 Path2D stroke + 渐变对象/精灵烘焙，CPU 成本随 段数×dpr 非线性增长——正是 iOS 明显差于桌面/Android 的原因。
- 流体求解器（~7.5k 格 × ~39 趟/步）在桌面 <2ms，非瓶颈；粒子/刚体步进同为次要项。

## 第一轮取舍：WebGL1

- **WebGL 1.0**：iOS 8+ / 全部 Android WebView 可用且 GPU（Metal）加速——兼容性最优解，正中"iOS 最差"的病灶。
- **WebGPU：不做**。iOS 支持太新、WebView 覆盖不足。

## 第二轮（本轮）：wasm 求解器——针对无 JIT 引擎（iOS WKWebView）

### 诊断：剩余瓶颈在 JS 数值循环

- 渲染 GPU 化后逐组件基准（真浏览器 Chrome CDP 实测，见下）：**流体求解器占整帧 CPU 74%**，批构建 25%，粒子可忽略。
- 平台事实（2026-08 查证）：**iOS 的 WKWebView（微信/App 内嵌浏览器）无 JS JIT**（Safari 本身有 JIT）。解释器跑数值循环慢 10~30 倍——流体从 0.6ms 放大到 6~18ms，加批构建轻松击穿 16.7ms 帧预算。这正是"Android Webview 快、iOS 差"的根源。**WebAssembly 不需要 JIT 权限**，无 JIT 环境也以编译代码速度运行。

### 取舍：MoonBit → wasm 求解器（逐位一致），不做 JS 代码生成/WebGPU

- 之前的"不做 WASM"决策基于"桌面 JS 已够快"——对本轮场景（无 JIT 引擎）不成立，故翻案。
- **强引擎（有 JIT）上 wasm 不更快**（实测 V8 慢 2×、JSC 持平）——所以 wasm 只用于弱引擎，**不降低任何现有好的体验**。
- 不用 Worker：wasm 已把成本打到可接受；Worker 只转移不消除，且采样仍需主线程读场。

### 改动

- **`native/fluid.mbt`（新，MoonBit）**：完整求解器移植。**与 JS 版逐位一致**（f32 存储 + f64 中间量 + 同运算次序），600 步后 u/v/t 与飞机轨迹逐位相同——两套引擎物理完全相同，切换无感，解法 URL 跨引擎通用。
  - 12.4KB wasm，**零导入**（无宿主依赖，任何环境可跑）；`bun run build:native` 重建，产物 `src/sim/fluid.wasm` 提交（常规构建无需 moon 工具链）。
  - 内存协议：JS 以 TypedArray 视图读写 wasm 线性内存低地址暂存区（u/v/t/solid），`heap-start-address` 隔离 MoonBit 堆；采样仍走 JS（零新增调用面）。
- **`src/sim/fluid-wasm.ts`（新）**：加载器 + `WasmFluid` + **引擎选择**。`FluidLike` 公共接口（fluid.ts JS 实现原样保留）；`LevelSimulation` 经 `createFluid` 工厂创建，可注入任意引擎。
  - **引擎选择**：启动时加载 wasm + 一次 JS 引擎速度探测（~2ms）。慢引擎（探测 ≥2.5ms，即无 JIT 的 WKWebView）自动用 wasm；快引擎保持 JS。探测与切换均逐位无损。
- **bench 三件套**：`scripts/bench.ts`（CLI）、`bench.html` + `src/dev/bench.ts`（**浏览器诊断页，iPhone 直接打开即测**）、`scripts/bench-browser.ts`（CDP 驱动 headless Chrome + CPU 节流，一键可复现）。

### 验证（真实浏览器，可复现）

- `bun run check` 全绿：typecheck + **84 测试**（新增 5 项：wasm 加载、流体场 600 步逐位一致、整局逐位一致、clear 一致、引擎选择）。
- `bun scripts/bench-browser.ts 1,6 3`（headless Chrome 150，CDP 实测）：

| 组件 | 1× | 6× 节流 |
|---|---|---|
| fluid.step JS | 0.73ms | 4.45ms |
| fluid.step wasm | 1.49ms | 9.23ms |
| LevelSim.step | 0.75ms | 4.54ms |
| batch 构建 | 0.34ms | 2.19ms |

- 解读：JIT 引擎 JS 已是正确选择（wasm 反慢 2×）；6× 节流近似弱机，无 JIT 时 JS 求解器会放大到 13~45ms（掉帧），wasm 恒定在编译代码速度（1.5~9ms），是唯一保帧路径。**iOS 实机数据请老大开 `bench.html` 测**（结果可一键复制回传）。
- 遗留：`AGENTS.md` 中"Canvas 2D"与仓库布局描述已过时（渲染已 WebGL、新增 native/），该文件受保护，已提示老大确认后更新。

## 补充：倍速（16×）卡顿诊断——物理无关，是帧预算余量问题

### 老大 iPhone 实机数据（bench-report.md，iOS 18.7 Safari）

| 组件 | iPhone JS | iPhone wasm | 桌面 Chrome |
|---|---|---|---|
| fluid.step | **0.488ms** | 0.647ms | 0.763ms |
| LevelSim.step | 0.485ms | — | 0.788ms |
| batch 构建 | 0.204ms | — | 0.373ms |

**结论：iOS Safari 的物理数值计算不是瓶颈**（比桌面还快，仅占帧预算 3%），wasm 在 iPhone 上反而更慢（探测逻辑会正确保持 JS 引擎）；"iOS 物理性能差"的原始假设被实测推翻。wasm 求解器仅在无 JIT 的 WKWebView（微信/内嵌浏览器）场景仍有意义。

### 倍速卡根因（帧成本 × 倍率线性放大 + 追帧爆帧）

- 16× 时每 60Hz 帧须执行 16 个 tick：iPhone 上 ≈ 16×0.49+0.2 ≈ **8~12ms**，顶到预算边缘，任何抖动（GC/热降频/Safari 合成）立即掉帧；CDP 6× 节流实测 16× 单帧 76ms（弱设备上每帧掉 5 帧）。
- **追帧爆帧**：旧 `MAX_TICKS_PER_FRAME=60`，掉一帧后单帧最多 60 tick ≈ 30ms（iPhone）——卡顿被放大器放大。
- **iOS 热降频**：倍速 = 持续 50%+ CPU，iPhone 主动降频。

### 修复

- `loop.ts`：追帧上限 60→**24**——最坏单帧 ≈ 12ms+渲染，欠账顺延下帧消化（短暂慢放而非爆帧）；稳态（16×=16 tick）与暂停回归均不触顶。`tests/loop.test.ts` 同步更新。
- `fluid.ts` + `native/fluid.mbt` **同步逐位微优化**（parity 测试守护）：固体索引表（enforceBoundary 免全阵扫描）、buoyancy 去分支（固体 t=0 不变量）、GS 预乘 divH2（f64 精度，与逐次计算逐位相同）、3×3 展开、行基提升、`|0` 替代 floor。JS 求解器 -17%（0.609→0.508ms bun），**所有平台所有倍率受益**。
- bench 新增「**倍速帧**」测量项（rate×tick+批构建），`bench.html?rate=16` 可直接在 iPhone 上量 16× 帧成本。

## 第一轮改动（渲染 GPU 化，未变）

**架构（公共 API 零变化，控制器/UI 无感）**

- `src/core/batch.ts`（新）：纯计算顶点批构建器——线段加宽、椭圆扇、径向渐变盘、虚线圆等全部展开为彩色三角形。无 DOM，可无头测试（tests 分层不变量保持：只 import core/game/sim）。
- `src/ui/gl.ts`（新）：WebGL1 薄层——单程序（位置+逐顶点色）、单动态 VBO、每帧一次 `drawArrays`；含上下文丢失/恢复处理（iOS 内存压力回收）。
- `src/ui/render.ts`（重写）：场景绘制全部输出到顶点批。删除 bg 离屏缓存、Path2D 分桶、渐变精灵 Map 等 Canvas 时代补丁。

**随重构获得的改进（非纯搬运）**

- **逐顶点颜色取代分桶近似**：旧实现受 strokeStyle 状态机所迫，透明度/温度离散分桶（4×5 档）；现在每段带精确 RGBA，一次提交——视觉更细腻且代码更简。
- **修复隐藏 bug**：旧 `drawPlane` 在高空（影子淡出高度以上）**连飞机本体一起 return，飞机凭空消失**；重写后影子淡出与本体绘制分离（详见 pitfalls D8）。
- 线宽几何化（GL lineWidth 多平台恒 1）；径向渐变用扇形逐顶点插值，免每帧 createRadialGradient。

**物理与调参（数值位级不变）**

- 热路径 `Math.hypot` → 内联 sqrt、投影迭代数提升为局部量——`tests/solutions.test.ts` 的通关时刻守护（±2s 实测全中）证明数值未漂移。
- 渲染 GPU 化后重调降级档位：移动端初始粒子档 128→240、轨迹点 12→24（旧限制来自 CPU 描边，现已移除），dpr 上限放宽至 2；自适应降级阶梯机制（EMA+慢帧计数）原样保留。
