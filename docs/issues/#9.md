## 需求拆解

1. 关卡内添加**实时计时 UI**（首版放 HUD → 老大反馈 HUD 已满，改放画面底部、要显眼）
2. 过关时展示耗时，**区分实际耗时与额外耗时**（惩罚）
3. **源数量越多惩罚越高** → 鼓励少用道具 + 更快通关
4. 重新开始重新计时，**惩罚性计时保留**
5. **计时必须实时更新**（首版事件驱动只在放置/过关时刷新 → 第三轮修复）

## 实现

**计时逻辑（`src/game/timer.ts`，无头可测，单一来源）**

- `SOURCE_PENALTY = 4`（每源 +4s，写有取值理由）
- `penaltySeconds(sources)` 计费 / `formatTime()`、`formatPenalty()` 统一展示格式（UI 不各自拼串）
- `LevelSimulation` 只调 `penaltySeconds`；**通关后 `time` 冻结**（展示的即是通关时刻，物理演示继续跑）
- 惩罚按**当前场上源数**计：移除源即减免；`restart` 保留源 → 惩罚保留 ✓

**实时计时 UI（`src/ui/run-timer.ts` 独立组件 + controller 每帧直推）**

- `SfRunTimer` Lit 组件（fixed 定位挂 document.body，底部居中 pill：squircle/blur/边框，与 chips 同风格）：`用时 12.3s 罚时 +12.0s` 并排，等宽数字防跳动，z-index 3（过关覆盖层 z-index 5 盖住它）
- **性能设计**：controller 渲染循环每帧调用 `timerEl.refresh(sim.time, penaltySeconds(...))`（纯函数、零事件）；组件内部格式化后文本不变直接短路——实际每 0.1s（1 位小数精度）才触发一次 Lit 更新
- HUD 保持原样；新手 caption 上移至计时条上方避让
- 踩坑记录：sf-game 的 shadow 无 `<slot>`，append 到宿主的 light DOM 子元素不可见 → 挂 document.body（已回写 pitfalls A9）

## 数值设计（4s/源 的理由）

关卡预算 4 热 2 冷（最多 6 源）：3 源基准解 30.3s → 合计 42.3s（+39%）——少用源的快解明显更优，但惩罚温和，不否定"多源兜底"的容错打法。

## 第四轮 UI 打磨（老大反馈）

- **底部文案保留原位**：新手 caption 恢复底部 `0.875rem` 原位；计时条在其上方（`3.75rem`），且**未放置任何源（文案显示期）时隐藏**（`hidden` + `:host([hidden])` 显式 display:none，防 :host 覆盖 UA 规则）——文案与计时条永不相撞
- **弹窗间距统一**：标题→文案 0.5rem；文案→耗时块、耗时块→按钮统一 **1.375rem**（实测 18px/18px 一致）；删除此前"负 margin 顶贴"的不和谐处理
- **耗时呈现**：独立暖色底卡（`rgba(255,237,209,.85)` + squircle）突出，字号 1rem、主值（用时/合计）700、额外 500 弱化——层级分明、位置居中和谐
- **第五轮（老大反馈"耗时块横向挤"）**：改**竖排三行**利用竖向空间——`合计 42.4s`（1.375rem/700 主成绩最突出）→ `用时 30.4s`（0.875rem）→ `· 额外 +12.0s（3 个源）`（0.75rem 弱化），行距 0.375rem，块宽 264px/高 97px 宽松舒适，不再挤一行
- **第六轮（老大反馈）**：
  - 弹窗"额外"去掉前置"·"，文案改为**说明道具来源**：`额外 +12.0s（使用 3 个道具）`
  - **底部 UI 一致性**：新手文案与计时条**同一位置**（底部中央边缘 0.875rem）交替出现——无道具时显示文案、隐藏计时条；放置道具后文案消失、计时条现身
  - **清空道具即恢复**：显隐条件从"累计放置次数"改为**场上源数**（`sources.length === 0`）——玩家移除全部道具后，底部文案恢复显示、耗时隐藏（实测：带 2 源进入 → 文案隐/计时显；撤销清空 → 文案恢复/计时隐）
