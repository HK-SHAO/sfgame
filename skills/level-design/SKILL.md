# 烧风关卡搭建指南（协议 v1）

本 skill 指导用「积木式」协议搭建关卡。核心信念：**少量精选的原子能力，通过组合产生乘法式/涌现式的关卡**，而不是堆砌新机制。每个关卡是纯数据（JSON），可在无头引擎内跑完整模拟，方便调试、测试与接入算法/AI。

## 1. 一个关卡长什么样

关卡是 `sfgame-web/levels/level-N.json`（内置关卡）或任意 `.json` 文件（DIY 传播）。完整示例：

```json
{
  "$schema": "https://sf.game.shao.fun/level.schema-1.json",
  "id": "xin-feng",
  "name": "信风",
  "tagline": "多站之旅",
  "win": { "title": "一站又一站", "text": "风把信从一站送到下一站。抵达不是终点，而是下一段路程的起点。" },
  "world": { "w": 76, "h": 56, "cell": 0.75 },
  "terrain": { "sdf": "30 - 8*ss((x-20)/16) - y" },
  "budget": { "hot": 3, "cold": 2 },
  "spawn": { "x": -4, "y": 16, "vx": 40 },
  "goals": [{ "x": 15, "r": 10 }, { "x": 52, "r": 9 }],
  "ambient": { "x": 2.4, "y": 0 }
}
```

协议规范 = `sfgame-web/levels/level.schema-1.json`（JSON Schema draft-07，编辑器自动补全/校验；关卡 `$schema` 绝对 URL 指向线上部署的协议文件，dist 根由 copy 插件随包发布）。`$schema` 是编辑器提示（可选字段），运行时校验以 `app/game/level-validate.ts` 为准、不依赖 `$schema` 值（schema 与运行时解耦，改版不拒绝旧关卡）。`id` 为小写 slug（`^[a-z0-9][a-z0-9-]{0,31}$`，URL 直传零转义、语义化命名；显示序号由关卡顺序派生，与 id 解耦）。URL 单参数 `lv` 双形态：slug 直达内置关卡，内联关卡 = base64url JSON（判别 = 先 slug 后 JSON 的 fallback，见 `app/game/state.ts`）。schema 只表达不依赖世界的静态约束；world 依赖的动态边界（x≤w 等）与 SDF 语法、固/气共存、网格 16..256 由运行时校验强制（`app/game/level-validate.ts`，两处镜像由 `tests/level-schema.test.ts` 守护）。构建产物 dist 根目录含同文件。

序列化选型：**JSON**（`JSON.parse` 零依赖解析，浏览器/脚本通用；不支持注释——设计说明放本 skill 或提交信息）；地形只用**一条 SDF 表达式字符串**（有符号距离场：>0 空气 / <0 实体，高度场 H(x)−y 是其中一种写法；精准、高密度、可表达洞穴/悬挑，可移植到任意数学工具），刻意不用采样折线（不精准）也不引 path（与表达式重叠、求值复杂——堆积功能）。

## 2. 原子能力（积木）

| 原子 | 字段 | 作用 | 示例关卡 |
| --- | --- | --- | --- |
| 世界 | `world` | 画布尺寸与流体网格（w/h/cell） | 全部 |
| 地形 | `terrain.sdf` | SDF 有符号距离表达式，定义空间与障碍（高度场/洞穴/悬挑） | 全部 |
| 预算 | `budget` | 热/冷源数量，资源约束 | 全部 |
| 起点 | `spawn` | 出生位置与初速度（可在画布外飞入） | 全部 |
| 站点 | `goals[]` | 抵达圆站点：`{x, r}`（r = 抵达范围半径，虚线圆即此范围，可逐站调整，校验 0<r≤15）；**飞机进入抵达圆即算"抵达过"（滑行同等计数），全部抵达过即过关，顺序无关** | 全部 |
| 环境风 | `ambient` | 常风 `{x,y}` + 可选温度偏置 `temp`（热=全域上升/冷=全域下沉，经浮力生效，[-10,10]；平衡升沉速 ≈ 11×\|temp\|：0.1 微风、0.3 玩法级、≥1 极端、\|temp\|≥9 单极世界，见下方量程说明）+ 可选潮汐 `tide{period,phase,ampX,ampY}` | L1/L2 常风、L4 潮汐 |
| 固定源 | `fixed[]` | 关卡自带的 `{x, y, kind:'hot'\|'cold'}`，玩家不可移除/撤销、不占预算（渲染为篝火/空调） | L6 营火、L7 冰窖、L10 焚风 |
| 风扇 | `fans[]` | 定向气流 `{x, y, dir(弧度), power(注入风速)}`；可选 `swing`（摆幅 ±弧度）+ `period`（周期）= 摇头风扇 | L8 鼓风、L9 钟摆、L10 焚风 |
| 关卡组 | `LEVEL_GROUPS` | 主页选项卡分组：**JSON 不声明归属，分组在 `app/game/levels.ts` 的 `LEVEL_GROUPS` 常量声明**（组名 + 组内 ids 顺序；解锁 = 首关恒解锁，其余上一关或本关有通关记录；结算「下一关」组尾跨入下一组首关） | 第 1 组「长风」、第 2 组「焚风」、第 3 组「烈风」 |

关卡文件**不内置解法**（免玩家翻代码作弊）：只记最佳过关耗时（progress.ts：单条最佳、与关卡内容 hash 绑定、localStorage 持久化），不记解摆法、进关不预置。

### 组合语法（乘法式）

六个积木本身简单，组合起来涌现出玩法：

- 热源 + 地形 = 上升风托升（L2「起飞」）
- 冷源 + 地形 = 下沉风压降（L1「降落」）
- 站点集合 + 地形 = 多段旅程（全部站点抵达过即过关；L3「信风」、L5「回归」）
- 常风 + 潮汐 = 风有涨落的节奏（L4「潮汐」）
- 环境温度 temp + 地形/源 = 全域升沉背景流：表达寒冬/酷热、逆温层，与热冷源叠加可造浮力净余谜题（temp 与源温同号增强、异号抵消）

**temp 量程刻度（均衡升沉速 ≈ 11×\|temp\| 单位/秒）**：±0.1 微风（背景氛围）；±0.3 玩法级（显著牵引飞机）；≥1 极端（飞机完全任风摆布，只能靠源链/地形造生存走廊）；**\|temp\|≥9 单极世界**：源温被 tMax=±9 钳制，temp≥+9 时最冷的源也无法让空气下沉（“无下沉世界”，冷源只能减弱升力）、temp≤−9 对称地“无上升”——浮力只剩一极，玩法退化为横风/地形谜题。极端量程是重型原子，一关只表达一个温度概念。
- 固定源 + 地形 = 世界自带的心跳，规划时把它算进去（L6 篝火接力、L7 冷源压顶）
- 固定源 + 风扇 = 热风走廊（L10「焚风」：风扇把火柱热流导向崖壁，涌现持续上升风）
- 热 + 冷 并排 = 对流传动的水平风（涌现，但实测强热柱轨迹混沌——见反模式）

设计任何关卡时先问：**我在组合哪些原子？有没有引入一次性特例？** 协议里出现新字段 = 新原子，必须能用在多个关卡上才值得加（第二关测试）。

### 风扇玩法经验（实测）

- 射流从风口起 ~4 单位内最强（约 1.3×power），~10-14 单位后消散——关卡跨度要短，或射流贴着地面让飞机滑行借用。
- 射流上方存在回流区：飞机在柱顶悬停时可能被回流抛高，摆幅越大越混沌——摇头风扇的摆幅控制在 ±0.4 rad 内、方向不越过水平线（永不上扬）可降低挂机与混沌风险。
- 固定源关卡红线：环境风要弱（≤0.8），否则挂机飞机沿平地无限滑行；目标放在墙/崖之后（需抬升才能进圈），挂机轨迹够不着。正 `temp` 会把地面挂机飞机抬离地面随常风漂移，叠加风险同理计入（常风+temp 组合尤甚），新关卡必须重跑 150s 挂机自查。

## 3. 地形 SDF 函数表

`terrain.sdf` 是有符号距离场 sdf(x, y)：>0 空气、<0 实体，世界坐标 y 向下。加载期烘焙到流体同规格网格（单一事实源：流体掩码/飞机碰撞/放源吸附/示踪粒子/渲染采样同一份场，校验要求世界内固/气共存）。两种写法：

- **高度场** `H(x) − y`：平原/山丘/台地（既有全部关卡）
- **真 SDF**：原语 + 并/差组合——洞穴/拱门/悬挑/浮石皆可表达（高度场不可）

支持：

- 变量/常量：`x`、`y`、`PI`、`E`
- 运算符：`+ - * /`、一元正负、括号（刻意不提供幂/取模）
- 剖面配料（以 x 为自变量，加进 `H(x) − y`）：`bump(c,w,h)` `gauss(c,w,h)` `smoothstep(t)（常用别名 ss）` `smoothstep(e0,e1,x)` `clamp(v,lo,hi)` `abs min max sin cos sqrt`
- SDF 原语（精确距离）：`flat(y0)` 半空间地基、`circle(cx,cy,r)`、`box(cx,cy,hw,hh[,r])` 圆角盒、`capsule(x0,y0,x1,y1,r)` 圆润山脊
- 组合：`min(a,b)` 并 / `max(a,b)` 差 / `smin(a,b,k)` 光滑并 / `smax(a,b,k)` 光滑差（k = 过渡带宽，min/max 是 k→0 的硬极限）；**挖洞 = `smax(a, -b, k)`**

常用配方：

```text
平原→高原平滑爬升：     30 - 8*ss((x-20)/16) - y           # x∈[20,36] 由 30 升至 22
对称孤峰：              44 - bump(42, 8, 24) - y           # = 24*ss((x-34)/8)*ss((50-x)/8)
平顶台地（L4/L7）：     44 - 24*ss((x-34)/4)*ss((50-x)/4) - y
高斯圆丘：              30 - gauss(20, 6, 12) - y          # C∞ 圆顶，3w 外视作平原
两级山脊（L5）：        30 - 6*ss((x-20)/10) - 6*ss((x-44)/10) - y
山中隧道：              max(44 - bump(42, 10, 26) - y, -circle(42, 36, 5))
地下洞穴：              smax(flat(40), -circle(30, 42, 6), 1.5)
空中浮石：              min(flat(40), circle(30, 20, 4))
```

`smoothstep(t)`/`bump` 自动钳制输入到 [0,1]，`bump`/`gauss` 两端 C1 平滑接平原（`gauss` 永不归零，3w 处残量 ~1e-4）。最大坡度 = 1.5×高/宽（`h*ss((x-c)/w)` 为 1.5h/w）：缓坡靠加大 w，与高度无关。飞机接触解算 = 法向投影 + 库仑摩擦（μ=0.3，摩擦角 ≈16.7°）：**比摩擦角缓的坡能停驻，更陡的坡无风自然下滑，垂直墙不可穿透**——陡坡/崖是天然屏障，上坡须风推且付出能量代价，这本身就是谜题设计工具。`smoothstep(e0,e1,x)` 为 GLSL 三参形式（要求 e0<e1），可从 GLSL 代码直接复制。

## 4. 设计要义（行业经验沉淀）

- **起承转合**：任天堂 3D 关卡（Hayashida 访谈）把每关做成「引入 → 发展 → 转折 → 收束」。教学关尤其要一段只教一个概念。
- **假设 → 挫败 → 顿悟**（Mark Brown）：先让玩家带着旧经验尝试，失败后重估，获得新认识。L3 的「第一站自然抵达、第二站被山脊挡住」就是这个结构。
- **解法先行倒推**：先手工摆出可通关摆法，再倒推地形/预算；早期关卡保证只有一个明显思路（Portal Test Chamber 01 的教训）。本站点语义是"全部抵达过即过关"（顺序无关），顺序感靠地形引导而非判定强制。
- **零操作挂机不能通关**（设计红线，验收流程含 150s 挂机模拟自查；#18 起不设自动回归）：但允许自然抵达前几站做「免费教学」。
- **克制**：不堆机制。一个关卡表达一个概念；新原子必须通过「第二关测试」——能想象出第二个不同用法才保留。
- **浪漫感**：#10 的叙事基调：信息论（信风逐站传递）、熵与时间之箭（潮汐）、庞加莱回归与宇宙演化（回归）。叙事嵌在 `win`/`tagline` 里，机制先成立，文案后补。

### 关卡组档案

- **长风（L1-5）**：教学组，一关一个概念（上升风/降落/多站/潮汐/回归）。
- **焚风（L6-10）**：固定源与风扇组（篝火接力/冷源压顶/鼓风/钟摆/热风走廊）。
- **烈风（L11-15）**：硬核 remix 组。前四关是既有地图的**只调参重编**——terrain/fixed/fans 位置/goals 位置/spawn 点位一律不动，只动 ambient（含 temp）/budget/半径/功率/摆幅/周期/出生初速；`ambient.temp` 担当主原子（冷场下沉逆风、热场上升无落脚）。L15 由外部图 hard1.json 改造（双岭天堑 + 低出生速 + 冷场，净浮力争夺）。难度来源 = 约束本身：资源收紧 × 环境敌意 × 落点圈缩小，组内按实测难度升序。**remix 组每关必须重跑挂机自查**（见 §5，存量 L9/L10 原版自身带病可挂机通关，会传染给 remix）。

## 5. 设计工作流

关卡设计后按需自检（不设自动回归；求解与玩法验证交给玩家实测）：

```bash
cd sfgame-web
# 无操作 150s：必须不通关（设计红线，挂机轨迹不得穿过任何抵达圆）
# 挂机轨迹确定性无随机，单样本即够；但 remix/调参后必须重跑（存量 L9/L10 原版自身带病）
bun run scripts/run-level.ts levels/level-N.json --sim 150
# 可解性自查（可选）：手摆一版确认可通关（结果不写入关卡文件）
bun run scripts/run-level.ts levels/level-N.json --verify 20-29.3-h,50-21.3-h
# 解精炼（可选）：以已知解为种子坐标下降，总耗时（含罚时）压到局部最优，见 §7；无参时自动以登记解为种子
bun run scripts/run-level.ts levels/level-N.json --refine 20-29.3-h,50-21.3-h
# 已知解回归验证：scripts/known-solutions.ts 登记了全部 15 关的解（精筛验证过、坐标 1 位小数），
# 物理/关卡改动后跑一遍，全部应仍通关
bun run scripts/run-level.ts levels/level-N.json --verify-known
```

**用调参破坏挂机时别单点碰运气**：挂机通关与否对参数非单调（实测同一风扇档 temp=-0.2 破坏挂机、-0.3 反而又通关）；用参数扫描把候选档全验一遍，选**全档失效**的鲁棒组合（辅助脚本 `scripts/tune-scan.ts`：批量改 ambient.temp/风扇功率后跑挂机）。

## 6. 解法搜索（多目标遗传算法，`run-level.ts --solve`）

> 现状：解法不随关卡发布，玩家通关自录；本工具仅供设计时自查可解性（离线，产物不入库）。

搜索参考解用**遗传算法 + 多 worker 并行**（`--workers`，默认核数−1），
优先级：

1. 必须通关
2. **总耗时最短**：总耗时 = 通关时间 + 源罚（4s/个）+ 贴地罚（1s/s，按物理时间逐秒累计）

> **为什么只比耗时**：玩家体验的关键是"多久能过关"，路程只是耗时的伴随物；
> 源个数与贴地时长都是成本（罚时与游戏同源 `app/game/timer.ts`），多放一个源、
> 多爬一秒钟地都要值回票价。爬行解物理上就慢，贴地秒数再逐秒加罚，无需硬性飞行门槛。

经验与参数：

- **搜索必须用精筛 `dt=1/60`**：粗筛 `dt=1/30` 是"另一套物理"，连已知参考解
  都可能假阴性（实测 L1 参考解在粗筛下 60s 不通关）——搜索直接跑精筛，
  胜点不再有 dt 差异。
- **坐标一律 1 位小数**：直达 URL 只保留 1 位小数，评估器对所有候选
  源做 1 位小数舍入后再模拟——3 位小数的刀刃解（实测 L2 有个 y=26.832
  的解，舍入成 26.8 就不通关）玩家无法复现，搜索阶段直接淘汰。
- **搜索 cap 默认 90s**（`--solve-cap`）：耗时优先下参考解可超 60s
  （L11-15 验收要求参考解 ≥60s），35s 快筛会漏掉慢而优的解；教学关参考解仍应 ≤25s。
- 候选源网格：x 每 2 单位一列，贴地/中空/高空三档高度，热冷各一；
  `--kinds h` 可只搜热源（教学主题约束，如 L1「上升风」只放热源）。
- **种子注入已移除**：关卡文件不再内置解法，种群全随机起步；连续多代无改进会停滞重启。
- 每次搜索输出**候选榜**（前 5 个互不相同的通关解），逐一 `--verify --robust`
  复核确认关卡可解即可。**鲁棒性 ≥6/8（75%）的关卡才算宽容好上手**（G7）；
  快而脆的解说明关卡对摆放过于敏感。
- 单次精筛评估 ≈ 1–2s（60fps × cap 35s）：32 个体、8 worker 约 4s/代，
  90–120s 预算通常够用；先想清楚预算再跑，别盲目加大。
- **GA 久攻不下时换种子精炼**：remix 关的原关已知解可直接当种子跑 `--refine`（地形同构，轨迹相近），比纯随机 GA 收敛快得多（实测 L12 GA 150s 无解，种子 refine 108s 通关并压到总耗时 76.7）。

## 7. 解精炼（坐标下降局部搜索，`run-level.ts --refine`）

以已知解（玩家解/参考解）为种子做局部优化，目标**字典序**：通关 → 总耗时（通关时间 + 源罚 4s/个 + 贴地罚 1s/s）最短 → 耗时；路程不参与排序。

方法：坐标下降，步长粗到细 2/1/0.5/0.2/0.1，邻域 = 单源单轴 ±step + 删一源；缓存门控（排序规范化键，同一多重集同键，只评未见摆法）+ worker 池并行 + 改进即打印（及时输出有效信息）。单关通常几十到百余次评估、一分钟内收敛。

```bash
bun run scripts/run-level.ts levels/level-N.json --refine 20-29.3-h,50-21.3-h [--refine-cap 90] [--refine-ms 180000]
```

经验：

- **玩家实局解可能无头不可复现**：实局源是飞行中择机放置的，无头评估所有源 t=0 全放，时序依赖的解复现不了（实测 L4/L6）；记录解时也可能超预算/笔误（L7 双热源超预算）。
- **基线不通关不必弃疗**：refine 按进展序继续爬升，能从不可复现基线一路爬进通关（实测 L4/L6/L7 全部救回）。
- **耗时优先会倾向单源解**：源少罚时少，GA/refine 会优先找单源捷径；若关卡意图是"多源配合"，验收时须显式跑单源搜索，确认单源解要么不存在、要么慢到不值得。

## 8. 反模式（实测血泪）

- **强热柱接力**：轻质量飞机在强热柱中轨迹混沌，摆放差 1-2 单位结果剧变（#8 报告）。避开「必须精确命中」的布局。
- **站点圆太小**：站点边缘擦过 = 几乎必败。教学关站点 r 用 9-11，给容差。
- **采样地形**：折线采样不精准、信息密度低。用表达式，一行顶几十个点。
- **粗筛即定稿**：`dt=1/30` 的胜点在 `dt=1/60` 会翻车。所有参考解必须精验。
- **单源捷径**：耗时优先的搜索天然偏好单源解，若关卡意图是多源配合，验收时没跑单源搜索就发布 = 大概率留下单源捷径。
- **一关教太多**：一个关卡放三个新机制 = 没人能学会。把新概念拆到后续关卡。
- **remix 免自检**：只调参不改地图不等于红线自动成立——存量 L9/L10 原版自身可挂机通关（遗留缺陷），remix 直接继承（L13/L14 初版均中招）。凡新关卡（含 remix）一律重跑 `--sim 150`。
- **单点调参碰运气破坏挂机**：挂机通关对 temp/功率非单调（混沌），改一个值就信一个值会翻车；扫描候选档选全档失效的组合。

## 9. 登记新关卡

1. 新建 `sfgame-web/levels/level-N.json`（不含解法；新关卡组先在 `levels.ts` 声明 `LEVEL_GROUPS` 条目）
2. 在 `app/game/levels.ts` 顶部 `import levelN from '../../levels/level-N.json?raw'`
   并加入 `LEVEL_TEXTS` 数组一行（JSON 以纯文本经 `?raw` 直读，随文件变更
   触发 vite HMR，无需构建插件）；按关卡分组把 id 加进 `LEVEL_GROUPS` 对应组，选项卡自动出现
3. 同步 `tests/level-format.test.ts` 的 id/组枚举（新关卡组加组名断言）
4. 走完第 5 节设计工作流
5. 把自查通过的解登记进 `scripts/known-solutions.ts`（回归基线 + 后续优化种子）
6. 选关页与 URL 直达（`?lv=N&s=…`）自动生效，无需额外 UI 改动；玩家通关后解法自动本地记录
